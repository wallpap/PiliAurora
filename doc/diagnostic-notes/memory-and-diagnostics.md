# 内存与诊断开销

## 区分存活对象与分配高水位

2026-10-31 的 Windows 浏览与播放流程复现了静置后进程内存偏高。隐藏保活页面树仍可能持有 Dart 状态和原生绘制资源，图片监听退出不等于纹理已释放。独立 D3D11 对照中，纹理释放后，存活设备仍保留写合并页；销毁设备后的另一轮对照中这些页回落。该对照支持本机存在图形设备分配高水位。

采集时分别记录 Private、RSS、私有工作集、Dart 堆、图片缓存及图形分配，避免跨口径相加或相减。ETW 的未归还提交页可按分配栈归类，但不直接说明当前活对象或所有者；符号解析前要核对 DLL 与 PDB 身份。比较前固定流程、采样窗口和进程，确认是否创建播放器及数据是否完整。

11 月 1 日的后续记录称，本机普通 FVM Release 在完整浏览和播放返回流程中通过当时的回落门槛；浏览结果距 500 MiB 门槛约 5.8 MiB。原始 ETL 和部分应用副本已清理。

旧版日志也出现过播放后内存保持在较高水平：1.5.0 的末五秒 Private 中位数约 636 MiB，1.6.2 的一次样本约 686 MiB。两次的内容、操作和缓存状态不同，只能用于确认现象曾出现，不能相减作为版本回归量。同名 GPU 适配器可能有镜像记录，统计时按 Flutter UI 对应适配器和采样时间去重。

## 4K 播放峰值与回落

2026-11-06 的 Windows 诊断主会话持续约 8 分 40 秒。进程 Private 峰值约 1236.6 MiB，结束时约 545.6 MiB；两次点播返回后的窗口中位数均约 555 MiB。插件输出、D3D/EGL 资源计数及待纹理注销数最终归零，弹幕过期任务预留为零。该样本未见持续增长或释放积压，不能排除更长时间运行的问题。

峰值发生在 4K AV1 播放启动约 7 秒、进入全屏附近。日志记录 14 个 NV12 解码表面，按 3840×2176 对齐估算约 167 MiB；两张 2560×1440 BGRA 输出纹理约 28 MiB，视频包缓存约 6.4 MiB。mpv 还记录了源尺寸和输出尺寸的浮点中间纹理调整，但日志不足以确认它们是否同时存活。

峰值附近的虚拟页增量主要为私有写合并页和读写页，GPU 用量同步上涨，退出后大块区域消失。播放关联的进程增量约 600 至 680 MiB，驱动、渲染中间资源与窗口合成的占用尚未精确拆分。解码池和输出纹理的名义字节不能代表播放器全部占用，也不能与 Private 或集显 local usage 相加。原包自报源码提交为 N/A，未采集 Dart 堆、ETW 分配栈和可用的引擎图形资源详情。

## 动图解码尺寸

2026-10-23 的合成图片探针发现，固定 Flutter 3.47.5 的多帧解码路径没有使用传入的目标宽高，GIF 和动态 WebP 仍按源尺寸产生帧。累计解码帧数也不等于同时驻留的图片数。排查动图占用时应分别核对 CDN 下载尺寸、解码后尺寸、活动图片引用和原生图形资源；应用侧针对 B 站质量型缩略图请求添加尺寸参数。

## 诊断采样本身也会影响卡顿

两轮 Windows Release 对照使用诊断开、关、关、开的稳态窗口，并以独立帧监听和计时器测量。该负载下，诊断开启时出现周期性的计时器和 DXGI 提交间隔变长；关闭窗口没有同样现象。PresentMon 的实际显示字段不可用，因此结论限于提交证据。

Profile 栈将部分耗时定位到主 isolate 的递归脱敏。随后记录显示，采集改为复制有界快照，递归脱敏移至导出后台 isolate，复制单条日志仍同步脱敏。离线函数对照显示采样路径耗时下降，后续没有新的 Release 呈现对照。检查诊断成本时应分别量测采集、来源读取、脱敏、编码与落盘，保持凭证保护边界。

## 页面复访长帧

同一轮对照在诊断关闭后仍观察到页面复访长帧。CPU 样本集中于列表恢复时的布局、子项挂载和语义树更新；独立测量的隐藏页绘制清理不足以解释整段长帧。采样 RPC 自身曾造成约两秒暂停，应避开采样边界，不把该暂停当作产品卡顿。来源记录没有同内容旧版本 A/B。

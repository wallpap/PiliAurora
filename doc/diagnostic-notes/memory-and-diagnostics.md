# 内存与诊断开销

## 区分存活对象与分配高水位

2026-10-31 的 Windows 浏览与播放流程复现了静置后进程内存偏高。隐藏保活页面树仍可能持有 Dart 状态和原生绘制资源，图片监听退出不等于纹理已释放。独立 D3D11 对照中，纹理释放后，存活设备仍保留写合并页；销毁设备后的另一轮对照中这些页回落。该对照支持本机存在图形设备分配高水位。

采集时分别记录 Private、RSS、私有工作集、Dart 堆、图片缓存及图形分配，避免跨口径相加或相减。ETW 的未归还提交页可按分配栈归类，但不直接说明当前活对象或所有者；符号解析前要核对 DLL 与 PDB 身份。比较前固定流程、采样窗口和进程，确认是否创建播放器及数据是否完整。

11 月 1 日的后续记录称，本机普通 FVM Release 在完整浏览和播放返回流程中通过当时的回落门槛；浏览结果距 500 MiB 门槛约 5.8 MiB。原始 ETL 和部分应用副本已清理。

## 诊断采样本身也会影响卡顿

两轮 Windows Release 对照使用诊断开、关、关、开的稳态窗口，并以独立帧监听和计时器测量。该负载下，诊断开启时出现周期性的计时器和 DXGI 提交间隔变长；关闭窗口没有同样现象。PresentMon 的实际显示字段不可用，因此结论限于提交证据。

Profile 栈将部分耗时定位到主 isolate 的递归脱敏。随后记录显示，采集改为复制有界快照，递归脱敏移至导出后台 isolate，复制单条日志仍同步脱敏。离线函数对照显示采样路径耗时下降，后续没有新的 Release 呈现对照。检查诊断成本时应分别量测采集、来源读取、脱敏、编码与落盘，保持凭证保护边界。

## 页面复访长帧

同一轮对照在诊断关闭后仍观察到页面复访长帧。CPU 样本集中于列表恢复时的布局、子项挂载和语义树更新；独立测量的隐藏页绘制清理不足以解释整段长帧。采样 RPC 自身曾造成约两秒暂停，应避开采样边界，不把该暂停当作产品卡顿。来源记录没有同内容旧版本 A/B。

# 历史排障经验

以下经验来自 2026 年 10 月至 11 月的调查，各项记录注明了当时的版本、设备和负载。当前流程见[维护与排障](../maintenance/troubleshooting.md)，本地材料按[实验资料归档](../../tool/experiments/README.md#实验资料归档)整理。

当前采用的修复、引擎、预算及剩余验收项见[默认构建与策略](../development/build-defaults.md)。本地材料保存在 `doc/dev/`，历史测量按相同条件对照。

## 播放与直播

- Windows 外部 AAC 音轨读取终止后，缓存可能继续播放很久，视频和整体 buffering 仍正常。2026-10-29 的受控 RST 对照中，缓存内 seek 未恢复音频，`audio-reload` 重新请求后音频时钟恢复。应同时记录音视频时钟、选轨、网络和缓存，覆盖长缓存耗尽场景。探针为 `tool/probes/playback/native_audio_stream_recovery.py`，实验使用空音频输出。
- 退出挂起先记录最后完成的关闭阶段，再查 Session、stop、卸载回执和输出释放。Windows 持续渲染曾饿死撤销任务；另一次返回卡住来自最大化恢复后根 `TickerMode` 未开启。先分清路由动画与播放器释放，超时结算不等于资源释放。
- Android Surface 重建时，旧 JNI 引用释放失败要保留所有权并停止重建；新资源完整创建后才登记，失败则回滚。主机故障注入不能代替设备验证。
- 更新退出需绕过托盘驻留，保存主窗口与小窗进度、释放播放器，再关闭 Hive。2026-10-28 的隔离 Debug 验证覆盖 17 个场景；强制结束可完成退出和文件释放，最后进度可能尚未保存。
- 黑闪日志先对齐故障时刻、版本、会话、程序路径和纹理身份。`surfaceGeneration` 增长不能证明重新分配纹理，不同会话码率样本不能拼成一次画质切换。2026-10-27 的直播黑闪缺少反馈时段，未在本机复现。
- 超分重建同时检查解码错误、实际硬解后端、有效纹理、音频时间线和播放意图。旧 mpv 补丁实验只覆盖本机 AMD GPU 与 `ao=null`，当前行为见[Windows 视频输出](../maintenance/windows-video-output.md#超分切换)。
- 候选探测中的 `Failed to create EGL surface` 不一定是最终后端失败。2026-11-06 的诊断最终使用 D3D11VA 并持续出帧；停止附近的 FLV/NAL 错误还需区分读取中止与源流损坏。`audio.recovery.healthy` 的 warning 等级不表示恢复失败。
- 排查重载黑屏时，同时检查实际像素、纹理身份和引擎导入状态。2026-11-14 的本机反例中，空描述符释放了 EGL Surface，句柄缓存却未清除；相同句柄恢复后仍跳过导入。帧消费回执发生在引擎导入之前，不能证明画面正常。修复及设备验收范围见[默认构建与策略](../maintenance/windows-video-output.md#原生资源与首帧)。
- 分片媒体 seek 需持续读取越过后续分片边界，仅检查落点会漏掉中途跳包。2026-11-10 的 libavformat 对照在先前跳、再回退后发现约 5 秒音频缺口；单次回退对照通过。复现条件和固定样片见[分片回退探针](../../tool/probes/README.md#windows-分片独立音轨回退回归)。
- 排查画面边缘色偏时，按时间戳对齐真正的新帧，并分别检查整帧、最坏行和局部误差；整帧均值可能掩盖单行异常。2026-11-07 的 AMD 离屏对照中，HEVC／AV1 直通硬解出现底边单行偏色，copy 和软件路径通过；色度采样修复后 21 组矩阵及 7 组旋转、10 位扩展检查通过。该结果未覆盖 HDR、声音、最终屏幕呈现或其他 GPU，修复的尺寸约束见[Windows 视频输出](../maintenance/windows-video-output.md#硬解纹理边缘)。

## 弹幕与帧呈现

- 更新次数、Build/Raster、GPU 提交和实际呈现须分开观测。保留目标时间、回调时间、位移、Raster 与 present 的同帧关联，缺失数据不借相邻帧补齐；250 ms 聚合数据只用于定位方向。
- 同时看逐帧间隔和 3、5、7 帧窗口内的速度误差及呈现延迟。长短帧交替可能让平均速度正常。运动位置使用帧目标时间，暂停及资源期限使用实际单调时间。
- Android 固定视频、目标帧率、刷新率和解码路径，分别测取图、提交与显示。重复重绘不应重复读取同一视频帧；2026-10-21 的单机 A/B/A 对照还发现 Raster CPU 亲和性影响等待时间，收益依赖设备调度。
- 设置 EGL 时间戳不能补回已错过的 deadline。扩展失败时若无法关联实际呈现，只能确认持续出帧和生命周期；回退、暂停、隐藏与恢复须分别验证。
- Windows DirectComposition 实验曾有通过与失败复采，回退路径未完成验证。采集应串行并控制主机负载，报告关联率和覆盖率，提交时间与实际显示时间分别记录。
- Android 约 120 Hz 的同机混合弹幕实验中，24 FPS 视频配 60 FPS 弹幕时，帧目标时间计算的速度已稳定，实际呈现速度仍约为媒体速率的 0.63 至 2.10 倍；480 帧中 69 帧偏差超过 10%。连续合成使异常减少到 12/479，但同进程 A/B/A 的进程 CPU 时间增加约 19%、Raster CPU 时间增加约 47%，且仍有相位跳变。长期功耗和其他设备仍待测量。
- 媒体时钟同步读取曾在 UI isolate 单次阻塞最长 40.75 ms；异步整组读取后仍需在结果返回时核对播放器、媒体、seek 和释放代次。2026-10-21 的候选六段短测通过相应阈值，但当时完整应用的帧计划路径尚未接入；现行引擎配置见[默认构建与策略](../development/build-defaults.md)。
- 2026-11-06 的 165 Hz 记录中，慢帧集中在页面与全屏切换附近；应将稳定播放和交互切换分开评估。该包没有 PresentMon 和逐帧显示时间，也无源码提交身份，不能据其确认屏幕呈现均匀，或把弹幕更新空档换算为显示丢帧。

## 内存与诊断开销

- 2026-11-11 的 Windows 调查修复了超分切源继承旧 shader、WebView 提前初始化和关闭后环境驻留。同内容从1080p超分切回4K的受控对照中，私有提交尖峰约2772降至831 MiB。源尺寸约束须在每次加载前、配置合并后应用，异步准备结果也要核对来源代次。
- 全应用策略共22次有效对照。Windows 网页环境按需创建，页面、验证码和Cookie操作持有租约，最后使用者结束5秒后释放。两次独立复测中，网页关闭后的进程树私有工作集中位约440降至311 MiB，浏览器子进程6降至0；超过宽限期后重开本地网页约多282ms。图片缓存保留64 MiB，16 MiB候选虽省内存，第二轮新增Image句柄约为对照三倍，未作为默认值。
- 完整应用本地AV1 4K60在本机AMD集显上完成四轮播放与自然返回，播放检查点私有工作集约745至766 MiB，返回静置约316 MiB。检查点不能代替全程峰值；线上DASH、HDR、其他GPU和长期负载未验收。原包匿名块缺分配栈，尚不能逐块追溯所有者。
- 此轮相关回归346项、13个Dart文件分析及固定发布引擎的正常Windows Release构建通过。探针与配置契约见[内存探针](../../tool/probes/README.md#windows-自动浏览与播放内存验收)；全程报告和校验清单归档在本地 `doc/dev/diagnostics/archives/memory-20261111/`，原始日志及账号种子不进入Git。
- 分别记录 Private、RSS、私有工作集、Dart 堆、图片缓存及图形分配，避免跨口径加减。隐藏页仍可能持有绘制资源，退出图片监听不等于纹理释放；分配栈代表首次提交路径，不能证明当前所有者。解析栈时核对 DLL/PDB 身份，并在释放后持续观察：本机独立 D3D 对照中，全部跟踪纹理销毁后写合并页仍可能延迟回落或保留至设备销毁，不能据此断定永久泄漏。
- 2026-10-31 的 D3D11 对照支持本机存在图形设备分配高水位；旧版本不同操作、内容和缓存条件下的内存值不能相减作为回归量。部分原始 ETL 和应用副本已清理。
- 2026-11-06 的约 8 分 40 秒样本中，Private 从约 1236.6 MiB 峰值降到约 545.6 MiB，输出资源计数最终归零。该时段未观察到持续积压，长期负载仍待测量。解码表面与输出纹理的名义字节不代表全部占用，不能与 Private 或集显 local usage 相加；驱动、中间纹理及窗口合成未精确拆分。
- 固定 Flutter 3.47.5 的合成探针曾发现动图目标解码尺寸未生效。核对 CDN 下载尺寸、实际解码尺寸、活动引用与原生资源；累计解码帧数不等于同时驻留图片数。
- 诊断本身会干扰测量。Windows 开／关对照曾出现周期性计时器与 DXGI 提交间隔增大，部分成本来自主 isolate 的递归脱敏。后续改为有界快照、后台导出脱敏，但没有新的 Release 呈现对照。应分别测采集、读取、脱敏、编码和落盘，并保留凭证保护。
- Gallery 区域解码的 2026-11-14 本机压力对照中，进程树峰值下降 23.19%，可见延迟 p95 增加 153 ms，原定延迟门槛未通过。测量版本与后续增加格式签名分流的最终源码不同；混合场景只有基线。比较内存方案时应固定源码身份，分别记录峰值、可见延迟和未覆盖场景；完整解码后裁剪不能证明区域解码降低了解码峰值。
- 关闭诊断后仍有页面复访长帧，样本集中于布局、子项挂载和语义树。采样 RPC 曾造成约两秒暂停，须避开采样边界；没有同内容旧版本 A/B 的样本不能用于判断版本回归。
- 没有创建播放器的大图浏览也曾出现显著 WC 增长，视频硬解不是该现象的必要条件。任务名额只限制并发数，输出预算只覆盖计账像素；完整帧回退、decoder 工作区和 Flutter/ANGLE 上传仍须分别观察。统一所有权后仍需分别测量这些分配。
- 动图缓存监听按流身份核对，防止旧流回收误删同键新条目；取消或隐藏后仍须检查未完成取帧和解码名额归还。独立音频的原生清理无法确认时保持租约屏障，后继实例等待交接，释放完成以原生回执为准。
- 区域解码像素比较须统一色彩空间、色度对齐和边缘 halo。WebP 缩放路径与原尺寸的滤波不同；CPU 样片的无缝结果不能推广为任意输入或 GPU 缩放。worker 退出与父进程上传资源释放也分别验收。

## 首页加载

首屏耗时拆成黑名单同步、内容请求、合作作者补查、过滤发布、视口补位和图片加载，分别记录耗时、返回数量、过滤后数量与可见数量。区分过滤删除与视口不足，也分别检查 App、Web 分页语义。

2026-10-30 的调查指出串行同步和批次补查会延迟首屏；后续实现已并行启动同步与下载，并逐卡展示合作内容。当前入口和约束见[功能地图](../development/features.md#首页与内容发现)，历史时序不再作为当前实现说明。

2026-10-12 的首屏调查发现，列表构建预加载区末项可能触发连续分页，动画骨架也可能扩大静态区域的重绘范围。定位时分别检查实际可视区补位、分页触发和绘制隔离；响应完成与慢帧相邻只能缩小排查窗口，不能单独证明图片上传或骨架是 GPU 尖峰的原因。两份操作内容与缓存状态不同的诊断包不能直接计算优化收益。

## 构建与状态

- Windows 构建产物出现 AppData 或 Temp 写入拒绝时，除文件 ACL 外，还要检查可执行文件和进程的完整性级别。2026-11-04 本机曾因仓库目录的 Low 标签使新 EXE 继承 Low，普通目录外的相同二进制以 Medium 运行并可写；DACL 中的 FullControl 不能覆盖完整性策略。该次标签已恢复，根因未归属到具体工具。
- 比较状态管理方案时，固定页面、请求、缓存和资源生命周期，分别测订阅范围、数据转换、分配及帧耗时。局部订阅可缩小重建范围，但选择器、长列表复制和重复缓存仍有成本；页面隐藏后仍需显式管理计时器、网络和原生资源。2026-10-12 的评估尚缺 A/B 实测，框架迁移的性能收益仍待验证。
- 分析 CI 耗时时区分并行任务的关键路径和 runner 总用时，并分别计量缓存下载、解压、依赖准备与编译。2026-11-05 的单次 Windows 样本中缓存解压远长于下载；Android 多 ABI 的首项包含冷启动成本，不能直接将串行耗时除以 ABI 数量预测矩阵收益。
- 2026-10-13 本机 Windows 干净 Release 对照，源码构建和预编译加 WebView 项目包缓存分别耗时 406.080 秒与 328.710 秒；每组仅一次，不能拆分两项优化的贡献，也不能推算 CI 收益。两份 3006 文件快照中 3003 个内容相同，差异为插件元数据、cnativeapi 预编译分支和各自安装路径。源码组先运行，优化组期间有额外 CMake 配置，系统缓存和后台负载未隔离。

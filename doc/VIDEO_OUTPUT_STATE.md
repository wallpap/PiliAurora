# 跨平台播放器纹理输出状态机

日期：2026-10-08。基于 Android 的有限状态输出策略推广到 Windows；不修改原生渲染通道和依赖。

## 平台状态映射

先识别平台，再将平台事件映射为统一的 `defaultPlayer`、`fullscreen`、`smallWindow`：

| 平台 | 默认 | 全屏 | 小窗 |
| --- | --- | --- | --- |
| Android | 非全屏、非 PiP 的设备播放界面 | 播放器全屏 | PiP，优先于全屏 |
| Windows | 应用最大化且播放器未全屏 | 播放器全屏，不要求窗口最大化 | 未最大化的可调整窗口，或桌面 PiP |

Android 旋转可触发同一播放状态的重新配置；PiP 内旋转不改变输出。Windows 不使用设备方向判断状态，监听窗口最大化、取消最大化和播放器全屏事件。初始状态向窗口管理器查询，不依赖持久化的最大化设置；异步查询不能覆盖较新的窗口事件。

## 输出规则

- `VideoOutputStateMachine` 统一状态转换、待配置标记和输出尺寸选择；`VideoOutputResizer` 保留目标合并、去抖和串行提交职责。
- Windows 默认和全屏按照当前物理视口选择输出尺寸，不超过源视频尺寸，沿用现有 Windows 尺寸计算规则。
- Windows 小窗恢复完整源视频输出尺寸，不随窗口拖拽、缩放或布局变化调整输出。退出默认/全屏进入小窗时必须恢复源尺寸，不能沿用先前缩小的纹理。
- Android 沿用源比例保持和竖屏视频排除规则；暂停期间原生队列停止新提交，恢复播放时提交已排队的目标。
- 同一状态中的普通布局变化不产生新目标。状态事件先等待布局帧；视口或源参数尚不可用时保留待配置标记，后续有效布局/源事件可完成配置。
- 媒体源参数/Android Surface 重建清除提交缓存并重新配置当前状态。DPR 变化重新选择物理输出尺寸。
- Android 原有设置项和平台编译开关保持不变；Windows 继续使用 `WINDOWS_VIDEO_OUTPUT_SIZE`。

## 验收

自动测试覆盖两端状态优先级、Windows 默认→全屏→默认→小窗的输出恢复、状态内布局去重、旋转、竖屏视频排除、无效尺寸和切源重配置；既有 resizer/native 队列回归仍需一起运行。

实机检查 Windows 窗口拖拽、最大化/还原、全屏进入/退出和桌面 PiP；Android 检查旋转、全屏、PiP、暂停/恢复和切源。单元测试与编译成功均不能证明 GPU 画面无闪烁或裁切。

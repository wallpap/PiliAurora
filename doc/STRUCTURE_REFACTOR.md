# 公共请求与设置备份结构重构

日期：2026-10-07。原始基线：`f675de667`；播放器修复已独立提交为 `c5dcda101`。这次重构沿用现有依赖、持久化格式和第三方包版本，共享 Flutter SDK / Pub 缓存也未改动。

## 公共控制器：统一请求生命周期

原来的列表和详情控制器各自管理加载标记、错误处理和业务响应，只用一个 bool 决定能否发起请求。刷新会先重置 page / cursor，随后因旧请求正在加载而被跳过，旧响应仍可写回；抛出的异常也会跳过最后的标记释放。

现在由 `CommonController<R, T>` 统一管理：

- `loadingState` 使用明确的 `Rx<LoadingState<T>>`，列表控制器的结果类型是 `List<T>?`，不再让基类接口暴露裸 LoadingState。
- 刷新启动新代次；只有最后一次查询可以进入业务响应钩子。旧请求不能覆盖新页面数据或释放新请求的加载标记；旧 HTTP 请求仍可能完成，但其结果不能再写回。
- 加载更多串行执行，列表需要有效首屏数据并且未到终点。失败的追加保留原列表与页号，允许重试。
- 页面关闭后失效所有响应；请求或业务钩子抛出的异常仍向调用方传播，但 finally 释放当前加载标记，不吞掉异常。
- 业务控制器保留已有 customGetData / customHandleResponse / handleError / checkIsEnd 扩展点；详情与列表只处理自身结果，不再各自复制网络生命周期流程。
- 列表拥有每页的可增长副本，追加时不修改 API 返回的列表，可接受固定长度与只读响应；元素对象不额外复制。

每页复制列表是为了取得可修改的所有权，不能据此判断内存或吞吐表现。刷新允许新的查询替代旧查询，请求频率仍由调用方的搜索防抖控制。

## 设置备份：格式和替换规则独立维护

`GStorage` 只负责打开 Box 和组装 `SettingsBackup`，导入导出从通用存储工具中移出。About / WebDAV 两个入口使用同一模块，不再为 JSON 编码依赖包含剪贴板、Toast 和异常捕获的 Utils。

- 保留既有 setting / video JSON 格式与缩进，不导入其他分区。
- 两个分区的结构与 Hive 键类型均在首次写入前校验，坏输入不会先清空有效设置。
- 用已有 collection 的 DeepCollectionEquality 比较嵌套值，仅 upsert 改变的键；相同备份不会写入或删除，也不会产生 Hive watch 事件。
- 全部 upsert 完成后才删除过期键，任一 upsert 失败时不主动删除旧设置。
- 恢复操作没有跨 Box 原子事务：写入失败时，部分值可能已经更新；删除失败时，旧键可能仍在。异常会交给调用方，下次恢复可以重试。
- 测试使用独占临时目录的真实 Hive，并对存储写入/删除顺序和故障注入做契约测试，不触碰用户数据库。

## WebDAV 同步：页面只组装配置与展示结果

进一步将网络连接生命周期与备份操作从 `pages/webdav/webdav.dart` 移入 `WebDavSettingsSync`：

- 页面在每次操作开始时读取连接配置与远端目录快照，组装现有 WebDavSettingsClient，不跨操作缓存含凭据的客户端。
- 同步模块负责目录准备、UTF-8 编码、上传/下载与 finally 关闭客户端，不访问 Pref / GStorage、设备信息或 Toast。
- 备份内容在首次网络等待前取快照，网络等待期间修改设置不会混入已经开始的备份。
- 恢复先完成下载并关闭连接，再校验和写入本地设置；坏 UTF-8、JSON 和分区结构不会清空现有设置。
- 同步模块直接组合现有的 WebDAV 客户端和设置备份模块，没有另建通用传输接口或配置对象。页面接收错误并统一显示。
- 页面仍提供原来的 init / backup / restore，远端目录和平台文件名保持不变。配置读取或内容导出失败也在操作 try 中处理，不再绕过失败提示。

新增 15 项同步测试：目录/上传/下载失败、内容快照、客户端按操作隔离、格式错误和存储错误；另有真实本机 HTTP WebDAV 客户端 + 临时 Hive 往返，验证中文路径只编码一次。测试只用回环地址、合成数据和独占临时目录，不接触用户 WebDAV 或数据库。

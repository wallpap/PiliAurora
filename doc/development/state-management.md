# 状态与异步结果

根 `ProviderScope` 位于 `lib/app/app.dart`。已迁移入口使用 Riverpod，路由和其他页面沿用现有实现；迁移前明确所有权及释放边界，再移除相应 GetX 注册。源码定位见[功能地图](features.md)。

## 所有权

| 状态 | 所有者与隔离键 | 主要入口 |
| --- | --- | --- |
| 消息、私信、未读、分享 | 主账号 Session，页面订阅或租约 | [消息模块](../../lib/services/messaging/README.md) |
| 当前主账号／推荐账号 | 分别订阅 Accounts 的角色通知，按账号对象身份发布 | `lib/services/account_providers.dart` |
| 搜索历史与记录开关 | 应用级 provider，Notifier 写历史，订阅 Hive 偏好 | `lib/pages/search/controller.dart` |
| 联想、热搜、搜索发现 | 页面 autoDispose family；完整热搜榜另有 provider | `search/`、`search_trending/` |
| 直播／空间／综合搜索 | 页面实例、已提交关键词、分类及目标／筛选快照 | `common/search/scoped_search.dart`、`search_panel/` |
| 黑名单、设备、日志、弹幕规则 | 主账号身份；日志另按类型隔离 | `blacklist/`、`login_devices/`、`log_table/`、`danmaku_block/` |
| 关注、关系、分组、关注直播 | 目标、类型、排序／关键词与账号；分组共享确认快照 | `follow/`、`follow_type/`、`live_follow/` |
| 空间列表、文集、PGC 索引、充电排行 | 页面实例、资源 ID／类型／筛选／等级与所属账号 | `common/member_feed.dart`、`article_list/`、`pgc_index/`、`member_upower_rank/` |
| 空间隐私、直播分区／标签／屏蔽 | 账号，屏蔽另绑定房间；Widget 持有编辑草稿 | `space_setting/`、`live_area/`、`live_dm_block/` |

表中页面入口相对 `lib/pages/`。FocusNode、输入、Tab、滚动控制器、路由与提示由 Widget 持有并释放；Notifier 返回业务结果。页面间使用构造参数、回调或窄信号，不通过 Get.find 互取控制器。

主账号与推荐账号按对象身份判断。同 UID 的新凭据也会使依赖重建；仅推荐账号变化时保留主账号查询及消息 Session。查询角色须显式绑定：直播搜索、推荐和 PGC 结果使用推荐账号，空间查询、隐私和屏蔽使用主账号；综合搜索的请求与屏蔽分别使用相应角色。

## 查询与分页

- 输入变化在防抖前使旧联想失效；清空、关闭或禁用联想均丢弃旧结果。提交关键词和筛选生成独立查询，页签计数来自当前有效快照。
- 刷新、切号、替换查询或释放后，迟到结果不回写。`AsyncValue` 错误或加载期间可能保留旧 `value`，显示计数、自动分页和写入资格须同时检查 `isLoading`、`hasError`，切号期间隐藏旧内容。
- `FeedPagination` 按实际滚动范围加载，以 `dataSource` 的对象身份隔离来源，`dataRevision` 触发快照检查；Riverpod 无需额外 stream。来源替换后，新分页不等待旧请求。
- 分页串行，失败保留内容和页码并显式重试。按领域 ID 去重；基于偏移的列表删除后重读边界页，防止前移遗漏；刷新或切号使旧分页失效。
- 过滤后空页按原始分页信息继续读取，游标重复或连续五页无增长时限界。关注直播优先使用总页数或过滤前总数；综合搜索保留首屏特殊卡片，后续页查视频，分页期间移除的项继续保持移除。
- 共享列表依赖成功快照：规则读取失败不以空列表覆盖播放器，专栏文集不混用旧元数据，分组计数不由未保存的勾选派生。商品无后续游标时保留服务端查看更多入口，充电排行保留首页最多 100 条的语义。

## HTTP 与写入结果

- 调用方须区分成功、失败、取消、无数据和待确认；保留原始原因与堆栈，提示不暴露凭据或响应正文。code/message/data 协议复用 `Request.requestApi`，显式声明 `ApiCallKind`，领域解码器决定可空语义；独立协议保留自身契约。
- 请求前固定账号，HTTP 账号与 CSRF 来自同一对象，多步操作沿用同一账号。写入关闭网络自动重试，无法确认服务端结果时保留 UnknownResult，消息沿用其 unknown 语义。
- 写入按账号、对象或业务串行互斥；异步返回检查账号、目标、查询所有者和页面存活。切号、刷新或离页停止后续步骤，迟到弹窗也失效。
- 草稿包含来源、内容和阶段，失败保留草稿或选择。分组、标签、隐私等仅在成功后更新确认快照；来源变化拒绝旧编辑，自己的新建结果可提供继续编辑的确认来源。
- 部分成功保留已确认步骤，例如弹幕规则删除成功但新增失败。远端成功不被本地清理、回调失败覆盖，Future 的失败由操作持有者消费，dispose 不发写请求。
- 成功写入刷新其他受影响入口，并废弃旧查询；播放器规则只在成功快照变化时同步。资源释放遵循模块协议，消息租约不替换为普通页面状态。

## 验证与迁移边界

按[测试目录](../../test/README.md)选择对应页面、HTTP 或服务回归，命令和平台前提见[构建与测试](build-and-test.md#静态检查与测试)。重点覆盖失败重试、同 UID 换凭据、刷新／切号／离页后的迟到结果、部分成功和订阅释放。真实服务、输入、WebView 及播放器显示需设备验收。

个人空间、收藏、历史和订阅有跨入口列表及写入一致性；推荐、登录、全局账号、播放、下载及直播连接还需评估缓存和资源生命周期。公共抽象由实际重复行为驱动，优先领域内直接 Notifier 与不可变状态。

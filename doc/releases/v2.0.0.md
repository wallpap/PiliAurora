# PiliAurora 2.0.0

相对上一正式发行版 [v1.6.9+610](https://github.com/wallpap/PiliAurora/releases/tag/v1.6.9)，本次更新集中修复播放资源交接、Windows 图片查看，以及操作失败和切换账号时的状态问题。开发构建默认采用已验收的引擎与策略，构建号与 CI 一样自动生成。

## 用户

### 播放、缓存与声音

- 修复 Windows 在媒体重载后可能持续黑屏的问题；旧媒体的纹理先完成释放，再交接新画面。
- 修复降低清晰度后保留过大的视频输出资源，以及媒体尺寸尚未确认时提前分配全尺寸输出的问题。切源前约束继承的超分配置，减少不必要的资源重建。
- 新增省内存、均衡、流畅优先三种视频缓存策略。默认均衡，下次加载点播媒体时生效；缓存内的短距离跳转继续复用已有数据，未缓存或已淘汰的位置重新读取。
- 修复加载、重载或跳转后缓存条等待下一次预读才更新的问题；缓存条可以随当前缓存边界回退。
- 画质、音质、编码和直播线路在新来源加载成功后才确认选择。失败时保留原确认值，并允许重试同一选项。
- 修复旧分集查询和过期播放事件影响当前媒体、恢复位置越界，以及全屏切换时布局或系统界面状态不一致的问题。
- 音频切歌和独立窗口接管声音时等待前一播放器的暂停与清理；修复部分控制失败后界面仍显示成功、旧页面释放时清除新页面媒体控制的问题。定时暂停等待实际命令完成再反馈。

缓存入口为“设置 → 播放设置 → 视频缓存策略”。直播使用独立策略；预读时长与字节容量共同限制缓存，分离音视频分别占用预算。操作说明见[播放与弹幕](../guides/playback.md)。

### Windows 界面与图片

- 主窗口改用自绘标题栏，随主题显示；修复标题栏提示被页面遮挡的问题。
- 图片查看器对支持的静态 JPEG、PNG、WebP 使用有容量限制的区域解码，缩放时补充可见细节。其他格式和不适用的图片沿用完整帧解码。
- 修复部分嵌入色彩配置被 Windows 解码器拒绝时加载失败的问题，增加回退；图片仍无法加载时显示失败提示。
- 动图最后一个监听者离开后释放解码资源，Windows WebView 按需创建，共享环境在最后一个使用者退出后释放。
- 限制窗口的图形缓存预算，并调整 AMD D3D11 图片上传策略。内存占用和加载耗时仍随图片、驱动、窗口数量及设备变化。

### 操作结果、草稿与账号

- 区分请求失败、无数据、取消和结果待确认。修复部分网络错误被当作空列表，以及保存尚未完成就提示成功的问题。
- 写操作不因网络失败自动重发。评论、收藏、关注、动态、资料修改等结果待确认时保留相应草稿或选择；涉及改名等操作时，先查询核对再允许继续修改。
- 切换账号、刷新、更换目标或离开页面后，丢弃已失效的查询、导航和提示，避免旧结果影响当前内容。覆盖搜索、个人空间、列表分页、二维码登录、投屏入口、评论和私信选图等场景。
- 下载创建在记录保存后才确认加入；文件删除失败时保留记录，弹幕更新失败时保留上次可用文件，避免一次操作重复报告完成。
- 修复截图、动态 WebP 导出、图片保存与分享中的临时资源和反馈归属问题；保存失败、权限问题与用户取消分别处理。
- 字体、主题、图标、隐私等设置保存失败时保留输入或已确认值；远端修改成功但本地同步失败时分别反馈，避免把已完成的修改当作未提交。
- 改进 DLNA 发现与连接失败后的清理和重试、启动失败提示、诊断导出及退出清理。

遇到“结果待确认”时，先刷新对应页面或核对聊天记录，再决定是否重试。投屏命令被设备接受不等于电视已正常播放，仍需观察实际画面和声音。

### 安装与更新

Android 提供 `arm64-v8a`、`armeabi-v7a`、`x86_64` 分架构 APK；Windows x64 提供安装程序和便携包。下载入口为 [GitHub Releases](https://github.com/wallpap/PiliAurora/releases)。

Windows 安装版先退出主窗口和独立播放窗口，再安装到原目录。便携版完整解压到新目录，账号和设置继续保存在 Windows 用户数据目录。更新后在“关于”核对 `2.0.0+构建号`。已有设置按各自的生效时机沿用，备份说明见[账号与设置](../guides/data-security.md)。

## 开发者

### 构建入口与版本

`tool/build.ps1` 默认构建 Release，自动装配仓库预编译引擎。Windows 使用 `windowsDwmPaced`，Android 使用 `androidFramePlan`；应用和引擎的模式、架构、补丁与摘要匹配后才继续构建。日常构建无需额外指定引擎路径或呈现定义。需要热重载时显式使用 `-Mode debug`。

```powershell
pwsh -NoProfile -File tool/build.ps1 -Platform windows
pwsh -NoProfile -File tool/build.ps1 -Platform android
```

版本名为 `2.0.0`；本地与 CI 共用 `lib/scripts/build.ps1`，构建号取 `git rev-list --count HEAD`。本地通过参数向 Flutter 和应用传入同一版本，不改写 `pubspec.yaml`。构建需完整 Git 历史；浅克隆先运行 `git fetch --unshallow`。环境、签名与输出见[构建与测试](../development/build-and-test.md)。

### 修改时需要关注的契约

| 领域 | 2.0.0 的约束与入口 |
| --- | --- |
| HTTP、页面与写入 | 区分失败、空数据、取消与待确认；请求固定账号，迟到结果核对来源，确认保存后再发布状态。见[状态与异步结果](../development/state-management.md) |
| 播放与原生资源 | 页面通过播放所有者提交命令，加载 ready 后确认来源；音频租约和原生释放完成后交接。见[播放状态模型](../development/playback-model.md)、[Windows 输出](../maintenance/windows-video-output.md) |
| 图片 | 共用资源调度与来源租约，取消后等待原生任务排空；区域输出与完整帧分别遵循释放协议。见[图片模块](../../lib/common/widgets/image/README.md)、[测试契约](../../test/common/widgets/image/CONTRACTS.md) |
| 回归与诊断 | 按模块选择受控失败、来源替换与资源释放回归；统一 Python 测试入口，实验资料生成本地索引。见[测试目录](../../test/README.md)、[工具入口](../../tool/README.md) |

## Agent

1. 从根目录 [AGENTS.md](../../AGENTS.md) 开始，按[功能地图](../development/features.md)定位本次修改的源码和回归，再读取对应模块契约。消息和私信继续遵循其 Session 与租约边界。
2. 修改构建、引擎或缓存策略时核对[默认构建与策略](../development/build-defaults.md)，以当前源码和引擎身份为准。历史实验保留当时条件，通过[归档入口](../../tool/experiments/README.md#实验资料归档)查找本地证据。
3. 交付时分别记录实际执行的测试、构建身份和设备验证。旧提交上的全量通过记录只适用于原提交；本次构建成功与目标设备画面、声音或性能验收分别记录。

## 验证范围

Windows 重载黑屏修复已有 NVIDIA 受控重载与画面检查记录。修复版 AMD 核显的 EOF、seek、连续重载及常规详情页真实音画仍需设备验收；Android 各 ABI 同样需要对应设备验证。

Windows 图片区域解码已有回归及压力对照，曾测得峰值内存下降，同时加载 p95 增加，原延迟门槛未通过。本版本保留该取舍；压力对照的版本、指标及延迟结果见[历史排障经验](../diagnostic-notes/README.md#内存与诊断开销)，当前实现见[图片模块](../../lib/common/widgets/image/README.md)。

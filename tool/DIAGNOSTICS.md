# 内置性能与诊断

入口：**关于 → 性能跟踪**。日志等级也可从关于页或原日志页直接调整，立即生效。所有设置都会保存。性能跟踪默认关闭；已有的关闭日志设置继续生效，否则默认等级为“警告”。

## 复现内存或播放问题

1. 打开“记录性能”。普通检查选 1 秒；捕捉短时峰值选 250 毫秒。
2. 日志等级选“调试”。需要 mpv 的详细内部事件时选“跟踪”。
3. 返回首页、动态或播放页，按发生问题时的步骤操作。
4. 回到性能页，停止记录，然后点击右上角“导出诊断包”。Windows 可选择 ZIP 保存位置。
5. 诊断完成后将日志等级恢复为“警告”。高详细度日志会增加格式化和写入开销。

日志与性能记录互相独立。日志等级为“关闭”时，仍可单独记录性能。关闭性能跟踪会移除帧回调和采样定时器。停止跟踪后的页面显示最后一次采样，不代表实时用量。开启跟踪的设置会在下次启动时恢复；不需要继续采样时请关闭。

## 指标范围

| 部分 | 记录内容 | 含义和限制 |
| --- | --- | --- |
| Windows 进程 | 工作集 RSS、启动以来峰值工作集、私有提交、CPU | 通过本进程系统计数器读取，不启动辅助进程。CPU 同时记录单核百分比和全机百分比，每次开启后的首样本为空。峰值由系统维护，可覆盖采样间隔内的工作集尖峰。 |
| Flutter 帧 | 帧数、慢帧数、UI 构建和光栅化的平均/最大耗时 | 每个采样周期单独汇总。构建或光栅化超过当前显示器刷新周期时计为慢帧；没有帧时平均值为空。 |
| 图片 | LRU 字节与数量、活跃/待加载图片数、缓存上限、活跃 codec 数 | LRU 字节仅是缓存账面值，不包括全部活跃图片、临时解码和 GPU 资源。 |
| 图片操作 | 文件读取、创建 codec、解码帧的进行中数量、完成数、失败数、平均/最大耗时 | 调试日志还会记录目标尺寸和解码帧尺寸。RGBA 字节是按宽高估算，并非额外内存分配。 |
| 播放器/解码测试 | 播放/缓冲状态、位置、缓冲位置、分辨率、实际硬解、编码、帧率、丢帧 | 跟随播放器注册和注销；同时记录预览缓存字节与上限。播放器没有提供的字段为空。 |
| 弹幕 | 缓存元素数、时间桶数、进行中分段数 | 对象数量可辅助判断增长，不等于独占内存。 |
| 网络 | 主 Request/Dio 客户端请求数量、状态、耗时与错误；调试时记录 host/path | 不记录查询参数、请求头或请求/响应体。Content-Length 是服务端声明长度，不是实际网络流量；图片下载器和 mpv 自身网络不计入此请求统计。 |
| gRPC | 解压与解析耗时、输入字节、是否在后台 isolate 执行 | 后台耗时包含调度及数据传递时间。 |
| 页面与版本 | 当前路由、版本、提交标识、会话时间、序号 | 可将峰值关联到页面和操作时间。 |

RSS、私有提交、各类缓存的数值不能相加。本工具不提供 Dart 堆、GPU 显存或各模块独占内存归因；这些字段不以零代替。非 Windows 平台当前仅读取运行时提供的 RSS/峰值 RSS，未接入进程 CPU 和私有提交采样。

解码器测试也复用 `ProcessMetrics`。其 CPU 指标已从系统整体占用改为 PiliAurora 进程占全机的比例，不再周期性启动 PowerShell。GPU 用量显示为不可用；内存为本轮采样期间的工作集峰值。

## 记录与导出

- 文件保存在应用支持目录的 `diagnostics` 子目录。
- `runtime.jsonl`：每个文件最多 2 MiB，最多 3 个文件。
- `performance.jsonl`：每个文件最多 8 MiB，最多 3 个文件。
- `.1`、`.2` 是较旧文件。达到上限后覆盖最旧文件。
- 页面最多保留最近 200 条运行日志；重启只扫描每个运行日志文件的末尾 256 KiB。
- 每个文件流的待写队列最多 256 条，每条最多 64 KiB。队列拥塞、超大记录或写入失败会增加丢弃计数，可在页面及导出记录中查看。
- ZIP 包含轮转后的运行日志、性能 JSONL 和 `manifest.json`。压缩在后台 isolate 中执行，文件快照与写入按顺序处理。
- 旧异常日志继续保留原页面及格式，单独轮转为 2 MiB × 3；ZIP 不包含旧异常文件。新的异常同时写入运行日志。
- “清除诊断记录”停止采样，删除运行日志和性能记录；旧异常日志由原日志页清除。

记录写入前会过滤 Cookie、Authorization、令牌、密码、私钥、URL 查询参数和本机用户目录等常见敏感内容，并限制文本和嵌套结构大小。数据仅保存在本机，不自动上传。

## 扩展与验证

统一入口是 `Diagnostics`：`log` 记录事件，`begin`/`finish` 统计操作，`register` 注册按需读取的指标。注册方必须在资源释放前调用返回的注销函数。指标应使用稳定名称，读取时不得复制大型缓存或执行网络请求。

`ProcessMetrics` 负责平台计数器，`DiagnosticRecordStore` 负责有界写入与轮转，页面仅通过 `Diagnostics` 配置、查询和导出。使用现有依赖，不需要 release VM Service 或额外运行时。

回归测试：

```powershell
flutter test --no-pub test/services/diagnostics_test.dart
```

覆盖日志过滤与脱敏、设置及历史恢复、停止采样、HTTP 成功/失败/重试、文件轮转和磁盘错误恢复、队列上限、ZIP 格式、Windows 原生计数器和页面交互。真实浏览/播放时的峰值变化仍需按上述复现流程采样确认。
